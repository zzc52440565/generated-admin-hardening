# SQL 重设计交付模板

这是模型生成交付文件的结构约定，不是可执行 SQL，也不是当前用户项目的事实。用目标项目真实内容填写；本技能没有具体项目脚本时，不预造业务表和过程。

## 方案摘要

说明项目/版本、SQL 来源、目标数据库与服务器版本、执行工具、数据保护范围、结构调整理由，以及当前是否仅生成、已部署、应用已接入。明确空库安装、保留数据迁移、教学验证三种用途。

## 对象与规则矩阵

逐项列出对象名称/类型、保留/重构/新增/移除结论、业务目的、源文件/代码证据、数据范围、规则唯一执行者、依赖、SQL 文件及调用方。CRUD 四项、视图、存储过程、触发器均有结论，不适用时解释原因和替代方案。

## 逐对象契约

每个 CRUD/视图/过程/触发器按以下信息交付，不只给建对象语句：

- 对象名、所属 schema、用途与代码依据。
- 输入参数/列的名称、类型、来源、可空/默认、校验；可信角色/租户上下文从哪里取得。
- 输出列/结果集/返回码、影响行数和错误处理。
- 真实表/列、关联键、业务粒度、状态条件与副作用 owner。
- 创建/调用所需权限、安全上下文、事务归属及并发方式。
- 完整定义所在文件、应用调用位置与旧→新迁移、创建拓扑及替换策略。
- 合法与非法样例、断言、验证状态和失败证据。
- 触发器另加事件/时机/粒度/条件与 OLD/NEW 对照；视图另加连接/聚合与敏感字段策略。

## 契约示意：不可照抄成项目事实

假设某项目真实存在“只有本人可修改草稿申请”的规则，则：

- 修改契约使用申请主键、可信身份、允许状态及所需版本条件；不是 `WHERE id = 输入` 就够了。
- 查询视图只承担已确认的关联展示，不宣称普通视图自动防越权；调用查询保留身份范围。
- 若存储过程接管“提交申请”事务，应用只调用这一条写路径；定义失败时整笔回滚的契约和稳定错误。
- 触发器若确实需要保障跨入口终态不可改，只验证真实状态不变量，不再执行提交事务的同一副作用；若声明约束即可满足，则说明触发器为何不应重复实现该规则，并给用户需求可落实的替代设计。

实际角色、表、状态和规则必须重新从用户项目提取，不能因为此模板就新增“申请模块”。

## 文件与操作指引

文件结构按 `references/sql-redesign.md`；优先沿用项目 migration。唯一完整.sql文件头标用途、目标方言/版本、前置依赖和执行工具，不得包含真实数据库凭据。本轮新建本地实例及所有归属明确的隔离演示／测试账号统一`conventions.localDemo.password`；种子按应用真实编码器保存并逐角色真实登录验证，不得用于生产账号，不改未知来源账号。对象定义集中到唯一.sql，参数绑定模板和断言放Markdown或测试程序，避免复制时执行测试写入。

给出实际安装/升级顺序、执行失败停止点、验证命令和恢复步骤。无法验证的恢复路线标为未验证，不提供虚假的自动回退保证。SQL 结构导入、数据库脚本、七图快速填写三种复制目标分别说明。

## 验收与图表同步

按 `references/sql-validation.md` 逐项记录实测，列出旧对象/调用路径已迁移或仍待处理。仅定义、未部署、未接入的对象不能画成运行中的能力。实际使用过程/触发器时，在时序、系统流程、DFD 和架构说明中体现真实调用与副作用，不把视图画成新的独立数据存储，也不把存储过程画成独立部署服务。
