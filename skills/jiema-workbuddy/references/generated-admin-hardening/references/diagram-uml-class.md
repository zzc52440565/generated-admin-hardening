# 领域类图快速填写

以下是随包提供的领域类图快速填写格式；实际解析和保存结果以 MCP 回包及网页回读为准。

只支持类、属性、方法、关系四种行。示例按贫血实体只声明真实成员，不凭空补方法：

完整可解析正文只维护在 [示例正文](../assets/quick-fill-examples/02-uml-class.txt)；阅读前先看 [统一业务前提与逐图解读](../assets/quick-fill-examples/README.md)。

- 属性/方法归属前一个 `类：`，也可写 `属性：订单.编号：String`。所有关系放在类声明之后。
- source使用真实代码类型或经解释的领域别名，没有真实方法就不输出方法行；design按有依据的领域类型及职责方案表达，并记录为设计。两者均不能按 CRUD 名称补造方法。
- 关系类型仅支持 `关联 / 聚合 / 组合 / 继承 / 实现 / 依赖`。继承、实现方向为子类/实现类指向父类/接口；组合/聚合说明所属方与部分方并与实际模型核对，不能仅凭外键断定组合。
- 只有无参形式 `方法：提交()` 的结尾 `()` 会被剥离；当前快填不能完整表达参数、可见性、基数、角色名、接口种类或枚举字面量，这些在可视化编辑中补充，别把 `+submit(x: T): R` 当原生语法。
- 不支持 Markdown 标题或注释行；名称避免包含用于分隔的句点、冒号和箭头。冲突或歧义时使用已有唯一显示名，并列出手工补充项。

**更新语义是完整文本更新。** 在“快速填写”打开后回填当前完整领域模型，应用时移除未出现的类、属性、方法和关系；保留匹配项ID及未由简化文本改动的参数、可见性等高级属性。改名按新目标项处理，引用必须在本次文本中完整声明，不能为空或漏掉关系端点。
成员保留按类与成员共同匹配，不将其他类的相同局部编号当作保留依据；同端点不同种类关系的身份不随文本行顺序互换。
同名歧义会整体报错，不进行部分应用。所有需要保留的类和成员必须出现在全文；不能把局部新增片段当成完整替换。高级属性仍可通过可视化编辑调整，但删除已有普通项不再需要另列人工清理表。

示例的组合关系来自教学前提中明确的生命周期约束；目标项目没有该依据时只能据实选关系。示例文件为 `assets/quick-fill-examples/02-uml-class.txt`。

本图采用design或source的依据范围、逐元素溯源、覆盖与反例要求统一见 [事实审核合同](diagram-facts-contract.md)。正文只写原生语法，解释和来源放事实报告；不支持的语义写入限制清单，不能偷偷丢弃。
