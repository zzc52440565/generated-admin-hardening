# 初始 SQL 重设计流程与交付

必读 [数据库重设计与证据合同](database-contract.md)，它定义数据全量重建、对象清单、真实回读与验收失效规则。

目标是让初始脚本成为与真实业务、最终代码和运行数据库一致的数据库方案。既有 SQL 也可能只是生成器模板，不能直接作为正确答案；不能止于排版、改名、随意增加对象数量。

## 1. 盘点输入与消费者

先读原始 SQL、migration、表/字段注释、ORM 模型、Mapper/Repository、服务事务、权限和真实用例。已获授权且有隔离数据库时再核对系统目录中的实际对象，记录来源与差异。

建立对象清单：表/列/键/索引/约束、CRUD 语句及调用方、视图、过程/函数、触发器，以及对象间依赖。登记方言、服务器版本、客户端/驱动、字符集/排序规则、时区、schema/命名空间、部署身份与必要权限。识别初始脚本里的硬编码数据库名、`DEFINER`、路径和演示账号，替换为项目真实部署方式。

缺数据库版本等信息时先从依赖、配置、已有语法和仓库文档查明。仍无法确定时，将受影响的高级语法标为待适配；不随意切换数据库。不要输出密码或把连接字符串复制进报告。

## 2. 业务规则与数据库责任

按真实业务编制“操作/规则 → 代码证据 → 参与角色/数据范围 → 表/字段 → SQL 对象 → 调用方 → 验证”矩阵。优先修复错误模型，例如错误的金额类型、缺失的主外键、不能表达的状态、关联孤儿、无唯一约束的业务单号。

允许根据当前 SQL 重设计请求修改交付脚本的结构，不受旧技能“一律不增删表字段”限制；仍须遵守用户的兼容/数据保护要求。涉及数据丢失的变更给映射、迁移与恢复路径。没有现存数据库时不伪造一份所谓“已迁移结果”。

每条规则明确唯一执行者：约束负责可声明的不变量，事务负责业务原子性，应用服务或过程承接业务写入，触发器仅承接明确需要数据库自动保障的规则。可多层校验，但同一副作用只能执行一次。

所有 CRUD、视图、存储过程、触发器类别都必须检查。已有对象逐个给 `保留/重构/移除`，缺失且需求需要的给 `新增`；业务不需要或引擎不支持时明确解释。用户明确要求对象设计时不能只说“ORM 已有所以不做”，应给可落实的责任划分和完整定义。

## 3. 按依赖实施

先锁定目标表/约束和对象接口，再设计视图/过程/触发器与 CRUD，随后迁移调用方和测试，最后统一验收。对象创建顺序按实际依赖拓扑排列，不固定要求所有过程都先于所有触发器；删除旧对象按反向依赖处理。

消费迁移包括字段/表名、视图列、过程参数顺序/命名、结果映射、影响行数、错误码、事务边界、批量语义、授权身份。若触发器接管了既有副作用，移除调用链中的重复执行；若移除触发器，确保所有写入口都承接原规则。不要保留失效兼容 wrapper 或两套写路径冒充迁移完成。

将教学 SQL 与实际应用路径分开。独立练习可定义教学对象，但须标“教学专用、未接入应用”，不得据此修改运行架构图。应用采用直接 CRUD 时，不要假称每个服务都调用了存储过程。

## 4. 交付文件及使用方式

最终只交付 **一个完整 `.sql`**（如 `database.sql`），用户一次导入就具备当前应用需要的结构、关联一致的演示数据和必要对象；不把不同对象拆成多份让用户手动合并。文件头标方言/版本、客户端、空库前提与失败停止方式。按真实依赖创建表、数据、视图、过程、触发器；触发器与种子先后由其实际副作用决定。

CRUD参数绑定示例、正反例、测试夹具和保留数据升级/恢复步骤写入Markdown或现有测试程序，不在默认安装时执行测试写入、不留下另一份安装SQL。若项目已有正式版本迁移，维护运行依赖但最终安装入口仍只有一个；是否需要额外交付升级脚本遵循用户特别要求，不能偷偷在安装入口执行破坏性升级。

视图/过程/触发器采用最小合理集合。先保留真正调用者所需对象，再决定能解释真实业务的少量演示对象；不为每张表机械生成对象，不为凑数量新增应用职责。没有必要的类别说明原因。
本地开发数据库（本技能新建的专用实例）和所有本轮交付的演示／测试账号，口令统一为 `conventions.localDemo.password`。用应用真实 PasswordEncoder/Hasher 编码，逐角色用 `conventions.localDemo.password` 真实登录；配置、种子 SQL、测试与账号清单同步。已有且归属明确的本轮合成账号不一致时，在已授权的隔离测试范围内纠正；不得修改真实或生产账号，不得接管来源不明的既有数据库；此时另建隔离实例或账号。不得修改认证算法、写明文哈希或增加登录后门。

被新文件完全替代的旧SQL、随机/测试数据脚本和重复副本，先核对引用/调用迁移、在最终目录外保留必要恢复材料，再从最终项目移除。SQL结构导入与完整数据库安装不同；Studio导入不保证自动部署高级对象，不再因此复制一整套安装文件。

“可从零安装”不等于“可安全重复运行”。`IF NOT EXISTS` 不会升级旧结构，不能用它掩盖漂移。明确定义新装重跑、migration 版本、对象替换与失败恢复语义；不默认给初始脚本加 `DROP DATABASE`、全表清空或关闭外键绕过校验。

数据库脚本使用数据库客户端或项目迁移工具；Studio 快速填写只接收对应图表文本。SQL 不得粘进图的快速填写框，也不要让用户把全部混合对象脚本当成结构导入协议。
