# 时序图：整套快速填写

系统时序和业务时序使用同一套中文行协议，整套图通过一个连续文本提交。以下格式随包提供；实际解析以 MCP 返回的校验结果为准。

完整可解析正文只维护在 [示例正文](../assets/quick-fill-examples/03-sequence-family.txt)；阅读前先看 [统一业务前提与逐图解读](../assets/quick-fill-examples/README.md)。

- 固定使用中文全角冒号 `：` 和 ASCII 箭头 `->`；模型不能擅自翻译关键字或改成 Mermaid 的 `->>`。
- 参与者先声明，名称唯一，并与每条消息完全一致；分类仅推荐 `actor / boundary / control / entity / participant / database / external-system`。数据库可以作为 `entity`；source代码没有独立服务时不凭空增加一层；design中的服务分层须有职责方案依据。
- 消息末尾类型支持 `sync / async / return`；`reply` 等价于 `return`，另有 `create / destroy / lost / found`。省略为同步。异步队列只在source真实存在或design明确设计时使用 `async`，不能把入队画成任务已经完成。
- 片段类型支持 `alt / opt / loop / par / critical / break`；开始与结束配对，`片段否则：条件` 用于对应分支。`激活：名称` 与 `结束激活：名称` 也要配对。
- 状态约束可写 `状态：订单：待处理`，必须对应真实状态。
- 单图底层存在宽松解析，整族入口增加了未知行与消息计数检查；仍须核对消息、片段与所有分支，不能把“未报错”当业务完整。避免在名称/消息尾部混入作为语法的词。

最终只有一份 `03-sequence-family.txt`。首行固定 `# 时序图图族 v1`，必须恰有一个 `root` 总图，其他节用唯一稳定英文key；总图加最多24张业务图。业务图数量按核心业务覆盖推导，不能固定为3张，也不能漏掉主要业务。

每个核心业务独立分节但放在同一份连续正文中。全部内容一次粘贴“快速填写”，整套校验与保存；漏写的旧成员会移除。只修改某张图时可用网页选择该图后可视化编辑；若选择文本更新也须保留整套其他成员。任一坏节整批拒绝，不让用户删标题后逐张试。

高级事件不能降级丢失，使用现有序列化器生成的 `规范JSON：` 节，并保留完整事件、参与者引用及稳定标识。示例 `assets/quick-fill-examples/03-sequence-family.txt`；单节示例仅解释消息语法，不能当默认最终交付。

本图采用design或source的依据范围、逐元素溯源、覆盖与反例要求统一见 [事实审核合同](diagram-facts-contract.md)。正文只写原生语法，解释和来源放事实报告；不支持的语义写入限制清单，不能偷偷丢弃。
