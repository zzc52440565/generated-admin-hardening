# SQL 与当前系统的兼容边界

“符合系统”首先是符合被改造项目的实际业务、代码和数据库；需要回填 CodeAutoGeneratorSystem Studio 时，再同时满足接收端约束。不能把 Studio 的内部数据库当成用户项目数据库，也不能为了套接收端模板擅自迁移用户数据库方言。

以下是随包提供的兼容性快照，不是永久保证。导入前通过捷码 MCP 的 SQL 预览获取当前方言、诊断和可提交状态；更新后以真实反馈为准，不要求访问捷码服务端源码。

## 1. 方言识别与生成目标是两回事

- 源方言枚举 `SqlSourceDialectSchema` 包含 MySQL、MariaDB、TransactSQL、SQLite、PostgreSQL、Oracle。
- 生成目标 `DatabaseTypeSchema` 为 `mysql / sqlserver / sqlite`。识别出源方言不等于该方言所有高级对象都能生成/部署。
- SQL 导入反馈区分 `sourceDialect`、`effectiveDbType`、`importCompleteness` 与诊断，可能有类型/默认值/约束投影。先核对并逐项交付差异，不把“成功导入”当无损迁移。
- 原生 PostgreSQL/Oracle 项目可按其方言重设计，但不能声称本系统的应用生成目标已原生支持它们；不以替换方言作为默认优化。

## 2. 结构导入不是数据库对象恢复

当前结构导入主要以 `CREATE TABLE` 等表结构形成项目模型，不能把非表语句当作已经恢复的运行对象。完整输入还可能受语法解析、降级和诊断约束。因此：

- 为 Studio 单独生成包含最终表结构、支持的约束和必要元数据的 `studio-import.sql`。
- 视图/过程/触发器另存部署 SQL；不要把它们塞进混合导入文件后宣称均已保存、下载或被应用调用。导入后核对实际反馈与生成结果。
- 表/字段、键、关联及模型变更同时检查生成消费者、Web/小程序/桌面目标的承载能力，不以解析成功代替目标应用构建与运行验收。
- 本包记录的解析行为只作为设计参考；版本与行为改变时以 SQL 预览和实际导入反馈为准。

## 3. 保留生成注解与权限含义

本系统 `@jiema` 协议版本为 2。输入已有协议头、数据库/系统名、表/字段标签、登录角色、授权或业务规则注解时，沿用真实序列化格式和校验器，不把注解当普通注释清掉。

重命名模型时同步所有注解引用、关联路径、登录身份和权限对象。没有足够依据时不编造注解，不把 SQL 的 `GRANT EXECUTE/SELECT` 等数据库权限与用户业务角色/RBAC 混为一谈。保留注解也不意味着无需检查实际后端授权。

## 4. 教学对象与实际运行对象分开

系统可输出基于结构的查询、视图、过程和触发器教学内容；这些内容不证明生成应用已经调用或部署了对应对象。

SQLite 引擎本身支持视图和触发器、不提供服务端存储过程；本包记录的当前 SQLite 教学内容不保证自动输出这些对象。**引擎能力、当前章节输出策略和应用集成能力分别核对**，不能说 SQLite 不支持视图/触发器，也不能给它输出 MySQL 过程语法。

教学章节中存在 INSERT、UPDATE、DELETE、单表/条件/分组/排序/子查询/连接查询、视图、过程及触发器分类。可以据真实目标设计组织交付，但内部 `viewSql/procedureSql/triggerSql` 等键不是公开手动导入接口；没有核对 UI 前不要承诺点某入口即可替换整个 SQL 方案。

## 5. 客户端、驱动和部署

MySQL 客户端的 `DELIMITER`、SQL Server 客户端的 `GO` 是客户端/批次处理约定，不能原样当普通 SQL 交给所有驱动。根据实际执行工具输出脚本，并在 README 写明客户端命令/驱动执行单元及停止条件；不能按分号盲拆过程/触发器正文。

DDL 是否隐式提交、对象替换语法、约束是否强制、执行身份和权限都按引擎与版本确认。没有真实部署环境时只交付定义与步骤，不运行未知连接，不把“一段事务包住所有 DDL”当通用恢复方案。
