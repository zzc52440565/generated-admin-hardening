# 用例图快速填写

以下是随包提供的用例图快速填写格式；实际解析和保存结果以 MCP 回包及网页回读为准。

完整可解析正文只维护在 [示例正文](../assets/quick-fill-examples/07-use-case.txt)；阅读前先看 [统一业务前提与逐图解读](../assets/quick-fill-examples/README.md)。

- 参与者顶格，前缀 `参与者：名称`；外部系统用 `外部系统：名称`。多个参与者用顿号：`参与者：教师、教务管理员`，表示这些角色共用下方同一个业务目标，不能据此扩大真实权限。
- 用例最多三级，分别 2、4、6 个 ASCII 空格，不跳级。第一层写业务目标，下级写实际子目标/业务步骤。它不是自动生成后端 CRUD 权限的脚本。
- 支持 `独立用例：` 后换行缩进填写无参与者关联用例。名称含顿号、换行等特殊字符时用 JSON 字符串，如 `参与者："教学、管理"、教师`。
- 普通名称 1～255 字；不添加 Markdown 标题、注释、`include/extend` 文本箭头或“系统边界”命令，这些不属于快填语法。复杂关系需要可视化编辑并按真实语义处理。
- 只有唯一匹配的既有项才可能保留稳定身份；同名不等于同权限。改名、删除后再新增同名节点会产生新的 manual ID，不能恢复原规范身份。完整原样回填允许零命令；真实修改出现多匹配时整体拒绝，不能通过改措辞反复碰运气。大批命令有保存上限，按系统提示精简或使用逐项编辑，不把完整替换拆成局部覆盖。

**更新是完整图族替换。** 应用时移除全文未包含的旧参与者、用例及对应关联，总体图和各角色视图按现有物化器同步；不会更改ProjectDesign或实际业务RBAC。匹配项的身份、有效高级关系和元数据按产品规则保留。
必须输出所有需保留角色的完整树，不能将某个角色的单独片段粘贴为全文。原样应用不产生新命令；空/非法/歧义文本、批次超限整体拒绝并保留草稿，不能按旧提示分成几次局部覆盖。
示例文件为 assets/quick-fill-examples/07-use-case.txt。

保存前必须回读当前版本与规范角色/用例身份，登记保留、删除、新增及来源差异。手工/AI新增目标只属于图稿表达，不进入规范权限投影；已有规范端点间缺失授权的关联仍非法。所选design/source依据有而 ProjectDesign 未登记的能力记入 `authorization.designDifferences`，不得伪装为已绑定权限，也不得为图稿可用擅改业务权限。保存后再次回读功能结构投影。

本图采用design或source的依据范围、逐元素溯源、覆盖与反例要求统一见 [事实审核合同](diagram-facts-contract.md)。正文只写原生语法，解释和来源放事实报告；不支持的语义写入限制清单，不能偷偷丢弃。
