# 权限核对与必要重构

先盘现状，不能把“脚手架权限都不可信”当成必须重做的证据。

1. 从服务端授权、角色配置、行范围、字段白名单、文件与任务入口建立事实矩阵。先确认项目绝对根路径和搜索范围，再枚举路由注册、类级与方法级映射（含继承、别名、条件注册），沿参数、Filter/Interceptor、服务调用到数据读写反查；无前端按钮的接口同样登记。每个入口在既有权限矩阵中记录真实 method/path、参数、源码位置、授权与副作用。
2. 与已确认业务职责比较。角色推导是建议，新增角色或改变职责须在当前授权需求内；不能仅为了完整而重建 RBAC。
3. 按角色核对菜单可见、操作可用、数据范围和字段可读写。前端隐藏仅改善体验，不能代替后端拒绝。
4. 复用统一鉴权与查询范围，不把多个手写判断散落到调用方。按 ID、批量、导出、下载、子资源和后台任务都须绑定真实主体/租户上下文。
5. 按上述真实入口及参数，以隔离测试账号执行正向和负向行为：未认证、跨角色、跨用户/租户、越权字段、伪造明细归属、异步执行时权限变化。分别记录 HTTP 状态、应用业务码、身份和数据副作用；HTTP 200 中的拒绝码不算业务成功。声明入口已关闭时，须同时给出路由移除/禁用或拒绝分支的源码依据，以及真实路径的实测；请求被认证层先拦截不能证明路由不存在。猜测多个地址得到 404、错误工作目录零命中、无菜单按钮或表暂时为零行，都不能支持“没有调用/写入口不存在/永远无数据”的结论。未完成枚举或实测的部分标 unverified。
6. 修正后对受影响角色矩阵回归；图表记录实际角色，不让用例快填反过来创造权限。

本地开发数据库（本技能新建的专用实例）和所有本轮交付的演示／测试账号，口令统一为 `conventions.localDemo.password`。用应用真实 PasswordEncoder/Hasher 编码，逐角色用 `conventions.localDemo.password` 真实登录；配置、种子 SQL、测试与账号清单同步。已有且归属明确的本轮合成账号不一致时，在已授权的隔离测试范围内纠正；不得修改真实或生产账号，不得接管来源不明的既有数据库；此时另建隔离实例或账号。不得修改认证算法、写明文哈希或增加登录后门。
