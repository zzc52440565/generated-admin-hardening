# 功能结构图快速填写

以下是随包提供的功能结构图快速填写格式；实际解析和保存结果以 MCP 回包及网页回读为准。

使用每级两个 ASCII 空格，最多五级，依次为系统、角色、模块、操作、具体功能。第一行唯一根节点且顶格，后续不能跳级。建议始终写明前缀，避免默认层级推断改变语义。

完整可解析正文只维护在 [示例正文](../assets/quick-fill-examples/01-function-structure.txt)；阅读前先看 [统一业务前提与逐图解读](../assets/quick-fill-examples/README.md)。

按角色组织所选事实依据中的业务能力。主从单据合并后，行项目维护通常放在主单操作内部；不能因此删掉独立库存或报表能力。主数据是否独立以已登记业务事实为准。

名称避免裸换行。确有换行时在冒号后写 JSON 字符串，例如 `模块："订单\n管理"`。不要混用空格宽度或在正文前加 `#`，否则会生成多余节点。

在对应图的“快速填写”粘贴并按实际界面应用/保存；快速填写显示完整树（含画布隐藏层），当前树节点和连接按全文重建，会尽力保留可匹配身份，但不能保证改名、移动后的所有绑定都保留。未填写的隐藏旧节点也会移除；仅修改某个可见节点请用可视化编辑，它保留其余隐藏语义。核对角色来源绑定与显示深度。完整示例见 `assets/quick-fill-examples/01-function-structure.txt`。

默认只显示到模块（子模块/具体功能开关全关），完整五层语义仍保留。分别检查module/operation/detail：当前显示层应按可见树紧凑排版，不能用完整五层宽度造成基础层撑散；开关变化后检查无重叠与等高竖排。只解析全文通过不证明这三种布局都可用。

规范功能投影以当前 ProjectDesign 权限稳定身份为准；手工功能树可表达已核对的设计或实现能力，但新增节点不意味着服务端已建立角色授权绑定。游客入口、登录等与规范设计不同的能力必须在事实报告中明确标为图稿扩展；禁止按显示名称修复或猜测权限身份。

本图采用design或source的依据范围、逐元素溯源、覆盖与反例要求统一见 [事实审核合同](diagram-facts-contract.md)。正文只写原生语法，解释和来源放事实报告；不支持的语义写入限制清单，不能偷偷丢弃。
