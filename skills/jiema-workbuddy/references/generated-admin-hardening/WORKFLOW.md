# 生成项目加固、SQL 重设计与图表同步

此技能随捷码 WorkBuddy 连接器打包，用于已有源码或已下载的生成项目。先读取该项目及其规则，确定用户授权的核心功能范围，再选择检查项；不把经验样例当成当前项目的需求。图表格式参考随本技能打包，无须再安装或下载同名技能。

运行本技能前读取 [捷码 WorkBuddy 项目流程](../../SKILL.md) 的目标与执行计划。`system` 或 `harden-only` 完成加固后交付系统证据；已有源码不因调用本方法库而新增账号授权、在线建项或图稿步骤。`full` 在加固冻结后交给主合同的 DIA 阶段，按最终实现制作图稿并由现有 MCP 保存、回读。图稿格式与来源绑定细则只在第 5 节引用的 DIA 协议维护。

## 执行边界

- 遵循用户指令和目标仓库规则。明确是只读审查、修复实施，还是只更新图表；只读请求不修改文件、数据或启动有写入副作用的脚本。
- 本地开发数据库（本技能新建的专用实例）和所有本轮交付的演示／测试账号，口令统一为 `conventions.localDemo.password`。用应用真实 PasswordEncoder/Hasher 编码，逐角色用 `conventions.localDemo.password` 真实登录；配置、种子 SQL、测试与账号清单同步。已有且归属明确的本轮合成账号不一致时，在已授权的隔离测试范围内纠正；不得修改真实或生产账号，不得接管来源不明的既有数据库；此时另建隔离实例或账号。不得修改认证算法、写明文哈希或增加登录后门。
- 用户要求 SQL 优化时，可在交付脚本中按真实需求重设计表、约束和数据库对象，并同步调用方；这不等于获得对已有库执行迁移、删表或改数据的授权。空库安装与保留数据升级分开，不能让“保护 schema”变成只改 SQL 排版。
- 修复授权覆盖范围内的缺陷并迁移调用方；不能据“业务上可能需要”自行新增支付、短信、审批、自动计费等产品能力。确有高影响歧义时提出具体问题，继续独立工作。
- 不自动提交、推送或发布目标项目。允许按连接器流程使用已授权捷码 MCP 工具调用捷码项目服务；不得自行调用目标项目生产接口。安装依赖、启动服务、数据库迁移和清理遵循当前环境权限；不把技能视为额外授权。
- 复用已有测试登录方式或用户提供的会话。不得为自动化新增认证后门、记录明文验证码，或反复登录触发锁定。

**必读执行约定**：[统一演示口令与页面可视复审](references/runtime-review.md)。下载后必须主动读取并执行本技能及其必读协议，不能等用户再次点名，也不能只看摘要或只运行检查器。v2.4.0 的首次登录页改造、逐角色全部页面复审和演示口令要求均保留。

## 1. 建立事实与完成定义

页面编排必读 [页面任务合同](references/page-task-contract.md)：先依据真实业务重设计目标菜单、页面与布局，再用 `scripts/page_tasks.py` 编译和续跑；不按脚手架CRUD菜单锁任务。一个角色×目标菜单×业务页面是一个任务，页内主从、按钮、接口、权限、修复和复测均不另拆任务。初始计划在差距阶段形成，数据库/权限变化后重新编译同步；可变队列在项目外，最终报告在源码冻结前写入。

先读实际目录、依赖锁文件、启动脚本、路由/窗体、接口、业务服务、模型/schema 和现有测试。记录：

- 项目类型、技术栈及真实版本；主要用户、现有角色、核心业务和应用入口。
- 逐角色完整枚举菜单及列表/创建/编辑/详情/弹窗/无菜单入口，建立菜单/页面 → 操作 → 接口/方法 → 权限 → 数据模型的映射；区分真实实现、空壳和未证实能力。无菜单接口也必须按 [权限方法](references/rbac-audit-redesign.md) 从真实路由反查，不能用猜测地址的 404 证明能力不存在。
- 当前改动、可运行命令、已知失败、测试数据归属；不要输出秘密或复制真实用户数据。
- 初始 SQL、后续 migration、实际数据库方言/版本、ORM/Mapper 和已有视图/过程/触发器；SQL 脚本、当前模型与数据库实态不一致时逐项记录，不能任意选一份当真。
- 任务范围、完成标准、依赖顺序和验证矩阵。非简单任务复用仓库账本；无约定时在约定输出目录记录简短计划。

运行故障复现可作为基线；不要为了“跑起来”擅自迁移数据库或覆盖运行进程。环境不足时标记未验证，继续静态分析。

## 2. 按证据选择改造

从 [audit-checklist.md](references/audit-checklist.md) 选择相关项；不同平台查 [project-type-matrix.md](references/project-type-matrix.md)。主从归并查 [master-detail-merge.md](references/master-detail-merge.md)，权限问题查 [rbac-audit-redesign.md](references/rbac-audit-redesign.md)，接口/数据契约查 [crud-rbac-gap.md](references/crud-rbac-gap.md)。需要具体实现提示时再读 [code-patterns.md](references/code-patterns.md)。

对每个缺陷保留触发条件、证据、根因、改法和预期验证。先完成同一依赖链的全部实现、调用方迁移和相关测试，再按矩阵集中验证；失败后只重跑受影响项。

提供初始 SQL 或任务涉及数据访问时，先按下一节形成数据库对象与调用契约，再收口应用改造；图表以最终接入的实现为准。

重点判据：

- 表单的关联选项、回填、边界校验和失败恢复正确；金额、权限、状态等关键值由服务端校验。
- 按钮对应真实能力，正常导航、下载、刷新、状态变化都可构成有效反馈；不能只认弹窗或提示。
- 筛选核对请求字段、后端条件、返回记录/总数与已知样本。行数未变化不能直接判错，参数变化也不能证明后端已过滤。
- 权限检查菜单、操作、行范围和字段；同时覆盖列表、单条查询、修改、导出及附件。权限矩阵以已确认业务为准。
- 完整加固首次执行必须改造登录页，并对每个菜单下每个页面做业务适配改造。必读 [逐页业务改造与循环复验](references/page-business-redesign.md)：按用户目标判断保留并优化列表、重做业务工作页或完善已有业务页，适合列表可保留，特殊业务不能只换皮或加按钮。必要时贯通接口/服务/权限/状态/事务，保留有效功能与schema红线。按 [前端与运行交付](references/frontend-and-runtime.md) 测量真实尺寸并留截图。
- 数据和图片先检查现有资产。对已授权的演示与测试数据按真实业务 100% 重新设计并重新生成，禁止保留脚手架随机数据或仅补齐缺口，采用幂等业务接口与隔离标识；图片优先复用合法素材，缺素材时说明而非编造已完成。

## 3. 初始 SQL 与数据库对象重设计

必读 [数据库重设计与证据合同](references/database-contract.md)。结构可保留，但数据必须全部重新生成；数据库门禁未通过不得进入业务验收。对象清单、数据规格、唯一 database.sql、五类回读与版本失效联动均按该合同。

**拿到初始 SQL 后，默认完整审查并重设计 CRUD、视图、存储过程与触发器，不能只格式化、加索引或补几条示例。** 原脚本对象和业务假设都需复核，缺失对象也纳入目标设计；每类给出保留、重构、新增、移除或目标数据库不支持的结论及依据。

先读 [sql-redesign.md](references/sql-redesign.md) 建立顺序与交付，再读 [sql-object-design.md](references/sql-object-design.md) 逐类设计。接收端为本系统时读 [sql-studio-compatibility.md](references/sql-studio-compatibility.md)，验收按 [sql-validation.md](references/sql-validation.md)。交付结构见 [SQL 交付模板](assets/sql-delivery-template.md)。

- 按真实业务重定字段类型、键、关联、唯一/检查约束、索引及数据生命周期；保持用户要求的数据与兼容范围，所有名称变化有旧→新映射。
- CRUD 分别覆盖新增、读取/筛选/分页/统计、修改、删除/作废；参数绑定、权限范围、并发、主从事务和返回语义一起设计。不是给每张表机械复制四句 SQL。
- 视图明确业务查询、投影、连接基数、统计口径及授权边界；存储过程明确调用方、参数/结果、事务与错误契约；触发器明确表、事件、时机、触发条件和副作用。全部引用最终真实表与字段。
- 用户明确要求这些数据库对象时，为目标数据库支持且业务可落实的类型交付完整定义与调用/测试 SQL；不能只因已有 ORM 就整类跳过。没有业务依据、与既有职责冲突或数据库不支持时，写明原因与能满足需求的替代方案，不凑对象数量。
- 一条业务写入/计算规则只由一个 owner 执行。存储过程、触发器与应用服务不能重复扣库存、累计金额或写审计；替换时同轮迁移 Mapper/Repository、服务、接口契约与测试。
- 最终数据库只交付一个完整可执行的 `.sql`，结构、演示数据、必要视图/过程/触发器按依赖排列；CRUD与破坏性测试放Markdown说明中，测试程序不作为另一份安装SQL。不能承诺导入 SQL 后系统会自动保留/调用所有视图、过程与触发器。客户端 `DELIMITER`/`GO` 和程序驱动执行也分别适配。
- 验证覆盖新装、已有数据升级、对象调用、失败回滚、跨用户/租户、批量与并发。没有目标数据库实测时标为“已设计/静态核对，运行未验证”，不把 SQL 文件生成当作完成数据库部署。

## 4. 验证并确认最终实现

按实际项目运行定向测试、类型/lint、构建和受影响业务回归。Web 用现有浏览器工具；小程序和桌面用对应工具，不能以 Web 构建代替。

优先复用仓库测试。可选的 [browser-audit.md](references/browser-audit.md) 与 `scripts/browser_audit.py` 只执行明确配置的本地页面和用例，需要现有 Python Playwright；不安装依赖、不登录、不扫描并点击所有按钮。报告区分 `passed / failed / unverified`，缺工具、缺数据或未覆盖场景不能算通过。

前端验收必须执行逐页“业务形态复审＋真实操作验收”，失败记录问题ID并返工，复验该页及共享受影响页，最终重新枚举菜单/路由/角色核对完整覆盖。按 [审查记录格式](references/page-redesign-audit-format.md) 交付 `docs/page-redesign-audit.json` 并运行 `scripts/check_page_redesign.py`；Spring/JSP 项目还会反向扫描控制器视图与非片段 JSP。漏页、未闭环、旧源码指纹、证据早于代码或明写“需人工核对”均不得标通过。脚本不能证明业务合理或浏览器实测发生；缺执行能力如实说明，不能删页凑通过。

验证完成后冻结“最终事实清单”：实际角色及权限、功能入口、类与方法、调用顺序、状态条件、数据读写、组件依赖、已部署且真实接入的视图/过程/触发器。区分“仅定义”“已部署”“应用已使用”；尚未接入的 SQL 不能画成运行中的能力。若后续代码或 SQL 变化，重新核对受影响证据和图表。

## 5. 图稿交接

加固结束只冻结真实事实与数据/对象版本。需要图稿时交给主技能 [独立图稿子系统](../diagram-subsystem.md)，复用 [图稿格式方法](references/diagram-workflow.md)，先读 [事实审核合同](references/diagram-facts-contract.md) 与 [七图及ER统一示例](assets/quick-fill-examples/README.md)，按真实代码逐行溯源、自审场景并运行事实门禁。保存失败只阻塞 DIA，不回退已通过的加固，不要求用户手工复制正文。

## 6. 交付与停止条件

交付修复说明、真实验证结果、未覆盖项、SQL 目标脚本/对象契约/迁移恢复说明、图稿子系统的保存/回读证据。只交付一个已修改的项目目录，不另留“修改前/修改后”、补丁副本、失效SQL和废弃图文；删除前核对引用与归属，有价值恢复证据放项目交付目录外。用户只要求部分能力时按其范围交付；SQL 不适用的类别也给出明确结论，不静默省略。图表回传以连接器命令及服务端回读结果为准；尚无命令或回传失败时保存项目外恢复材料与精确失败图种，不把手工搬运作为默认路径。类图、用例图和架构图均按完整文本更新，未包含的对应元素会移除；用例图必须交付全角色的完整图族文本，不能只贴某个角色片段。保留项的高级属性和有效高级关系按产品规则保留。

启动与完成后留运行按 [frontend-and-runtime.md](references/frontend-and-runtime.md) 执行。实际打开登录页供用户预览，在最终改动部署后用项目已有的隔离验收账号或本轮新建演示账号分别按角色登录复验，并报告可访问地址；不得交付时主动停掉用户要看的服务。

当授权范围内缺陷修复、逐页业务改造与复验闭环、SQL 重设计与调用迁移完成、相关验证有结果、七图资料已按范围交付后收口。未通过页面不能以整体已完成掩盖。列明仍阻塞或未验证的事项；不以“无限循环到所有功能合理”为停止条件。清理仅限本轮登记、独占、已无人使用的临时产物，保留交付与失败证据。
