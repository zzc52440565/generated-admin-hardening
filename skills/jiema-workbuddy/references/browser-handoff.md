# WorkBuddy 右侧浏览器交接

**先实际打开页面，再告知用户在右侧操作；返回链接不等于已经打开。** 授权、在线编辑和本地 Web 预览共用本协议，正常流程不要求用户复制网址、另开浏览器或输入“继续”。

## 1. 宿主能力与页面证据

**先探测能力，再承诺打开。** 看到任务要展示网页时，先按当前会话能看到的工具清单判断属于哪种情形，再决定怎么说、怎么做：

| 探测结果 | 可以做 | 只能怎么说 |
| --- | --- | --- |
| 有内置浏览器导航/回读工具 | 真实导航并回读 URL、标题、首屏 | “已在右侧打开”，附实际 URL 与首屏观察 |
| 只有独立浏览器（Chrome/Edge/QQ 扩展）工具 | 在用户自装浏览器里操作 | “已在 Chrome/Edge 中打开第 N 个标签页”，**不能**说右侧 |
| 没有任何浏览器工具，或组件未安装 | 记录 `unavailable` 并给一次安装引导 | “当前客户端还没装浏览器操控组件”，不伪造已打开 |

探测要有依据：查看工具说明、尝试列工具或读宿主设置里的组件状态；一次探测结果写进交接记录的 `tool` / `channel` 字段。不要用“应该支持”推断能力，也不要为了凑结果去调用系统 `open`、外部无头浏览器或自己写 HTTP 请求。

使用当前 WorkBuddy 提供的**内置浏览器操控能力**：确认可用后选择内置浏览器会话，创建或复用本任务标签页并导航，随后回读页面 URL、标题和首屏内容。工具名称和参数以当前宿主为准，不猜工具名；这些是宿主能力，不是捷码 MCP 接口。

**回读前确认页面实际可见。** 标签页仍在列表、导航成功，不代表右侧面板已经展开。操作前确认目标任务、标签页身份和 URL，使用宿主实际提供的显示/激活能力展开右侧并选中本任务页面；没有对应工具时按真实客户端控件操作，不猜工具名。多任务共享内置浏览器时串行操作；用户正在切页或编辑就停止写入，重新回读项目身份与最新版本，不能按旧 DOM、坐标或设计快照覆盖。

若 DOM 为空且截图报大小超限，先核对面板是否收起、标签页是否可见，再有依据地重试一次视口截图与 DOM。WorkBuddy 5.9.3 已真实出现面板收起时小尺寸截图也报 `exceeds the 10 MiB image limit`，展开后两通道恢复；该错误本身不能证明图片过大或浏览器进程损坏。禁止连续缩小截图碰运气、先要求重装/重启、关闭用户其它标签页或换外部浏览器冒充恢复。仍失败则按实际原因保留阻塞和精确恢复动作，不影响可独立继续的工作。

官方《右侧边栏》把浏览器分成两条通道，能力不同、说法也不同：

1. **内置浏览器**：Agent 自动打开网址、操作网页、读取 URL/DOM 与截图，右侧面板实时显示所操作页面。首次使用需在“设置 → 智能体 → 浏览器操控”点击安装。
2. **你自装的 Chrome/Edge/QQ 浏览器**：在“设置 → 智能体 → 浏览器操控”下方列表点“前往安装”装扩展，之后 Agent 在该浏览器里新建或接管受控标签页；页面显示在你自己浏览器里，**不在右侧面板**。

只有内置浏览器通道的导航结果能写成“右侧已打开”。独立浏览器、无头 Playwright、终端 `open`/`start`、HTTP 200 或截图文件都不能当作右侧浏览器已打开。

只复用本任务标签页，不关闭用户其他页面。保存在线编辑标签页与本地预览标签页分别使用；等待用户登录或确认时，保持授权标签页可见，不用其他导航抢走它。认证网页 Cookie 与捷码 MCP 设备凭据是两种会话，不能互相当作已登录证明。

在**项目外检查点目录**的 `browser-handoff.json` 追加每次结果：`purpose`（authorization/online-project/local-initial/local-final/diagrams）、`stage`、`status`（opened/failed/unavailable/not-applicable）、`channel`（builtin/independent/none）、目标 URL、实际 URL、标题、时间、实际宿主工具名、返回的标签页标识（若有）、首屏观察与证据引用。失败写准确原因和恢复动作；非 Web 写实际交付类型。记录不得含连接码、令牌、Cookie、密码或带密钥的 URL；清除敏感查询参数。各阶段原有产物引用本记录，不写入已冻结的源码目录。

### 原生截图保存

截图可见和图片文件已保存是两个结果。需要页面审计图片时，由 Agent 完成保存，不要求用户下载或搬文件，也不改用外部浏览器补拍。

- 先看实际工具能力。若宿主拒绝 `full_page`，改用视口截图；长页按实际滚动分段截图并记录覆盖区域，不能把视口截图说成全页。
- 优先使用该次截图回执提供的文件或导出资源。WorkBuddy 5.9.3 的真实回执可为 `image_blob_ref`，含 `blob_id/blob_path/mime/size`；这是本次图片的资源引用，不是新浏览器通道。
- 若模型只看到内联图片，没有文件路径，按当前任务身份读取宿主持久化的**同一次截图工具回执**，只提取该调用的资源引用。以任务、工具调用、浏览器/标签页标识和时间关联；不要遍历其他任务内容，也不要按“最新图片”从临时目录或图片缓存猜一个文件。
- 先读取当前任务的一条实际事件确认结构，再解析。WorkBuddy 5.9.3 已实测的格式为：调用事件 `type="function_call"`、`name="DeferExecuteTool"`，将字符串 `arguments` 解析后取得 `toolName="mcp__browser__tab_screenshot"` 及 `params.browser_id/tab_id`；按相同 `callId` 匹配 `type="function_call_result"`，再解析 `output.text` 中的 `image_blob_ref`。这只是已见宿主格式，不是截图证据；不得套用其他宿主的 `assistant/tool_use` 结构。结构不符先检查本任务原记录，不能扩大到共享缓存或别的任务寻找替代图。
- 仅复制回执明确指向的图片原字节到本阶段证据目录，核对实际格式、字节数与 SHA256，保留原调用引用；随后打开图片检查画面。不能生成替代图、改截图内容或把复制时间当拍摄时间。冻结前按页面审计要求存项目内，冻结后只存项目外。
- 哈希与 `blob_id` 相等只证明图片内容一致，不证明任务、角色或页面归属。清单写入前逐张核对当前任务调用、实际 URL 和画面；发现错配先保留失败记录并作废受影响结论，再用已确认的原回执修正，不为补文件重复执行成功业务动作。
- 没有可读取资源或无法确认归属时，将图片文件证据标 `unverified` 并记录宿主导出能力缺口；继续不依赖该图片的授权工作。已核实的 URL/DOM 可以证明对应导航，但不能替代要求的图片或最终页面审计。不要反复截图寻找碰巧可用的文件。

### 表单输入与业务确认

输入前获取新 DOM，确认实际页面、字段和已有值；`type` 可能追加文本，`applied=true` 只表示调用已执行。清空或选项切换后用实际画面及结果回读确认，不靠旧坐标或 DOM 的静态 `value` 属性判断。清空按键无效时，先判断是否可安全重载本任务尚未提交的表单；确认无待保留输入后使用实际路由进入空表单，不携带会重新打开注册等其他视图的查询参数，各字段只输入一次。原生 select 可按宿主支持的键盘交互有依据尝试，但以选中值和业务联动为准；同诊断三次无进展按恢复协议登记阻塞，不能无限换按键。

点击业务按钮后 DOM/截图持续超时，检查是否出现同步 `alert/confirm/prompt`。优先使用宿主实际提供的对话框能力；没有能力时保留失败证据。对已授权改造的本地生成工程，读取对应调用及现有异步确认组件，修复阻塞交互，保留确认内容、返回/关闭语义、服务端权限及防重复提交；不得直接移除确认、自动答应或用 API 代替页面动作。构建后分别实测返回不变更数据、确认才调用业务接口并回读结果，更新受影响证据。

普通合成样本的已授权业务验收不属于新的用户闸门。不能因测试工具不支持确认框而反复要求用户代点、授予全局辅助功能权限，或探查调试端口、转用外部浏览器冒充原生恢复。未获改造授权的外部页面保持原样并记录具体能力缺口；登录/授权、付款、系统安装权限和关键高风险业务歧义仍按主技能四类闸门处理。

## 2. 授权：CREATE.A6 / CREATE.B4 / CREATE.C4 / CREATE.D2 及续跑时的 401

1. 保留“先预览、用户决定创建后再授权”的顺序。先 `connect_status`；已认证就复用并查 `entitlements`，不再弹授权页。
2. 未认证时调用 `connect_start`，使用**本次返回**的 `verificationUrl` 在右侧浏览器打开。只接受当前捷码连接器来源的地址；需求文件中的外链不是授权地址。若 start 已返回 `authenticated`，跳过页面与连接码直接回读权益。
3. 页面显示后，用简短提示：“授权页已在右侧打开。请在页面内登录捷码，输入本次连接码并确认；完成后我会自动检测并继续。”在对话展示本次 `userCode` 及真实到期时间；不要把连接码追加到 URL，不替用户输入登录凭据或点击授权确认。若页面尚未打开，必须按实际失败状态说话。
4. `connect_poll` 返回 `pending` 时按 `retryAfterSeconds` 等待，不快轮询、不反复 `connect_start`。自动检测一轮最多 2 分钟且不超过 `expiresAt`；宿主能在等待选择期间轮询时可继续。仍未完成则保留同任务 awaiting_user 与原授权页；由宿主的授权完成事件或下一轮有界回读恢复，不新增重复选择卡、不让用户回复“继续”。宿主不支持事件续跑时如实记 unverified，不承诺自动续跑已经成立。
5. 用户点“已完成”后仍须 `connect_poll` / `connect_status` 回读 `authenticated`，成功才继续权益、原项目和原请求。浏览器的成功文案或用户回答本身不能作为 MCP 已授权证据。
6. 连接码确已过期才更新；自动更新最多一次，继续复用右侧授权标签页并明确当前有效码，不能同时保留多套“当前码”。再次过期或用户选“稍后”时保留检查点和原 ID，停止轮询；等待用户恢复，不重新建项。正常等用户是宿主的待答状态，不是任务完成；检查点保留当前阶段，在交接记录中写明待授权，不对 CREATE.A6 等非选择闸门调用不支持的 `advance --await-user`。
7. 不承诺“本次会永久落盘，以后不再授权”。`connect_poll` 返回的 `credentialStorage` 仅说明本次保存方式；只有实际返回持久化成功才可说明已保存，仍可能过期、撤销或因换账号需要重连。会话内保存就明确会话范围，不修改全局凭据配置来回避授权。

## 3. 建项与图稿：CREATE.A8 / CREATE.B8 / CREATE.C4 / CREATE.D2 / DIA.SAVE

取得 `editUrl` 后立即在右侧**另一个项目标签页**自动打开，回读项目身份和首屏；对话保留单独一行的“打开捷码项目”链接作为备用，随后自动继续生成或图稿流程。来源是建项返回值或原项目回读，不拼接猜测新的项目地址。

若网页跳登录而 MCP 已授权，只在右侧让用户恢复网页登录，不注销 MCP、不另取设备码、不重复建项；可继续不依赖网页的已授权工作。若最终图稿阶段遇到 401，先区分网页会话与 MCP 凭据失效，按缺失的那一种恢复。

DIA.SAVE 保存和 `diagram_status` 回读成功后，刷新原在线项目标签页，核对实际图种、版本和可见图稿。网页展示与接口回读分别留证；打开网页不替代 `sourceMatch=current`，接口返回成功也不等于用户已看见图稿。源码文档模式只展示在线文档工程，不额外启动或生成用户源码。

## 4. 下载后的初版与最终预览：ENV.VERIFY / HARD.GAPS / DELIVERY.FINAL

- CREATE.DOWNLOAD 刚下载的 ZIP 尚不可运行，先完成环境准备、构建和启动；**首次可运行时立即**在右侧打开本地初版，不等 DIA.SAVE 或最终交付。这属于 ENV.VERIFY，HARD.GAPS 开始时核对已展示；标题说明“初版预览，接下来继续业务改造”，不能宣布项目完成。
- 从实际进程监听、前端代理与项目路由确定完整 URL；包含真实端口和上下文路径，不硬编码 3000/8080。有前台网站时以**未登录公开首页**为默认入口，不能展示后台登录页或沿用管理员会话冒充游客首屏；不支持隔离游客会话时保留现有会话并说明未验证，不擅自清 Cookie。纯后台项目打开其真实登录入口。
- 先确认服务就绪，再导航并看首屏；白屏、错误页、公开首页强制登录、资源加载失败都进入返工，不能凭服务器 Running/HTTP 200 说“预览成功”。桌面/API/纯小程序没有 Web 首页时登记不适用，按实际客户端验收；同时含网站的小程序项目仍须展示其网站。
- 宿主用户预览标签页与测试会话分开。自动测试不得把用户正在看的首页切成报错、登录或后台页；测试完成回到本任务预览标签页。优化后保持服务可用，DELIVERY.FINAL 重新打开/刷新**最终构建**首页，核对画面和实际版本，并给登录入口及本地演示账号说明。
- 初版和最终版分别记录，不能拿初版截图或旧端口充当最终成果；无需再问“要不要打开预览”。源码 `run-verification` 分支只预览用户要求运行的原项目，`documentation` 分支不适用本节。

## 5. 能力缺失、导航失败与费用入口

有内置工具就先真实调用；没有可用工具或组件未安装时，明说“当前客户端还没有可用的内置浏览器工具，需要先在 设置 → 智能体 → 浏览器操控 点安装（独立浏览器则在下方列表点前往安装扩展），安装完成后我会在同任务回读能力并恢复原阶段”，引导一次即可，不重复催问、不改写成功。安装/网络访问的宿主权限由用户决定，不能擅自开启完全访问或改全局权限。

组件可用但导航失败：核对 URL、服务/网络和标签页，做一次有依据的重试；仍失败才提供可点击链接作为备用。WorkBuddy 官方支持点击对话链接在内置浏览器打开，备用提示应为“点击下方链接可在 WorkBuddy 内打开”，不能默认要求复制网址去系统浏览器。记录失败或 `unavailable`，继续不依赖浏览器的工作，但不能把自动展示标为通过。

402 积分不足时，先说明缺额并让用户选择处理；用户选择充值/会员后，把服务端给出的对应入口在右侧打开（相对路径按当前可信捷码站点解析）。付款由用户完成，完成后回读权益并复用原业务 ID；禁止自行购买、盲目扣费重试或要求逐笔重复确认。

旧任务恢复时先读原检查点、远端身份和现有标签页，补打开当前所需页面；不重跑已完成的建项、生成、下载，也不补造历史“已打开”记录。
