# 逐页前端改造与运行交付

完整加固第一次执行就必须落实，不等待用户第二次强调。页面能打开或按钮可用不等于前端改造已完成；只读审查或仅更新图表时按用户范围。

1. 先读路由、导航、JSP/模板/组件，列出登录及每个页面、角色和主要操作。启动真实项目，提供可访问URL让用户看当前效果，不等待用户回复才继续。启动失败优先修依赖、项目内配置与构建，凭据缺失等硬阻塞如实报告。
2. 登录页必须有与业务相关的视觉、清晰身份/账号/验证码/错误反馈和手机布局。其余页面逐页确定信息密度与结构：看板突出待办和统计、列表突出筛选与主操作、表单按业务分组、详情突出状态与上下文、业务操作提供完整反馈。真实改造信息层级、布局、留白、字体和组件，不能仅改主题色/标题就算完成。视觉应统一且有该项目自身特征，不能生成完全一样的外观。
3. 每页记录“问题→布局方案→改动文件→桌面/手机几何→截图→实测操作”。共享样式可以复用，但逐页核对表单、弹层、长表、空态、窄屏及不同角色；无须改的页面仍给证据与原因。逐页检查真实渲染，不用源码行数代替尺寸。
4. 重新生成的所有本地演示账号口令为 `123456`；用实际PasswordEncoder/Hasher生成兼容编码，不为便利改用明文，也不批量重置真实数据库。按角色正常通过验证码、会话、菜单及数据权限实测；不能只证明哈希函数正确或只写账号说明。
5. 最终交付目录只有一个已修改项目、一个完整数据库.sql和七类图最终正文。清理已证明被替代的旧副本、重复SQL/图纸、补丁和本轮临时文件；保留有意义的测试和文档，不按扩展名乱删未知文件。恢复材料放交付目录外。
6. 部署最终代码后实际打开登录及核心页面，再次用123456登录并检查console/backend。结束前报告URL、启动命令、演示账号、使用的代码/构建版本与运行状态。用户要预览的进程保持运行，不能惯性执行“清理全部服务”；旧服务无法证明代码同步时不要冒称最新版。

验收数字必须真实：页面覆盖数、待改/已改/无需改/未验证数、按钮通过/失败/未测、不同角色登录、桌面/手机可见尺寸、SQL对象数量与用途。未验证项目明确记录，不能仅build成功就宣布完成。
