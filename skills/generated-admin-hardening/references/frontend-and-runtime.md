# 逐页前端改造与运行交付

完整加固第一次执行就必须落实，不等待用户第二次强调；只读审查或仅更新图表时按用户范围。

1. 先按 [逐页业务改造协议](page-business-redesign.md) 枚举每个角色的所有菜单/页面及无菜单入口。先启动真实项目并打开登录页，提供可访问URL供用户预览，随后继续工作。启动失败优先修依赖、项目内配置与构建；凭据缺失等硬阻塞如实记录。
2. 登录页必须改造为符合业务的视觉和清晰身份/账号/验证码/错误反馈及目标窄屏布局。其余页面逐页选“保留并优化列表／重做业务工作页／完善已有业务页”，给出任务与代码证据；特殊业务要改操作流程和必要实现，不能只换色、改标题、改共享CSS或一律把列表改卡片。
3. 遵循统一且有项目特征的布局、信息层级、字体、留白与组件。逐页核对表单、详情、弹窗、长表、空态、错误恢复及不同角色；复用组件不代表可免审其他页面。测量真实渲染尺寸、溢出与可操作性，允许业务表格内部滚动，不用源码/DOM行数代替几何。
4. 按业务协议完成“清单→逐页判定→实现→业务复审＋真实操作→失败返工→受影响复验→最终全量核对”。以 [审查记录](page-redesign-audit-format.md) 保留问题闭环和证据；结构检查通过不能冒充业务通过。
5. 重新生成的所有本地演示账号口令为 `123456`；用实际PasswordEncoder/Hasher生成兼容编码，不改用明文，不批量重置真实数据库。按角色正常通过验证码、会话、菜单及数据权限实测；不能只证明哈希函数正确或只写账号说明。
6. 最终只交付一个已修改项目、一个完整数据库.sql和七类图最终正文。清理已证明被替代的旧副本、重复SQL/图纸、补丁和本轮临时文件；保留有意义的测试和文档，不按扩展名乱删未知文件。恢复材料放交付目录外。
7. 部署最终代码后实际打开登录及核心页面，再次用123456登录并检查console/backend。结束前报告URL、启动命令、演示账号、使用的代码/构建版本与运行状态。用户预览的服务保持运行；无法证明旧服务同步了最终代码时不要称最新版。

验收数字必须真实，区分逐页业务复审、操作实测和结构检查。无法打开/未测页面列明原因，不从清单里删去；不能仅build成功就宣布完成。
