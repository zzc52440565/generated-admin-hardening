# 从最终实现到图表

## 事实提取

先读最终代码，不复述旧需求或生成器初始图。统一一份术语表：角色、模块、操作、领域类、状态、数据存储、外部系统、技术组件。每个关键元素记录 `项目相对路径:行号` 与符号；行号易变时同时给方法/类名。配置只记录键和用途，不输出凭据。

| 图 | 主要事实来源 | 需要避免 |
| --- | --- | --- |
| 功能结构 | 已注册页面/窗体、操作处理、后端授权 | 把每张表直接变成菜单，或把隐藏菜单当权限证据 |
| 领域类 | 领域对象、枚举、成员、实际业务关系 | 把 SQL 外键当继承，编造 getter/业务方法 |
| 时序 | 实际入口到业务服务与持久化的调用链、分支及异步处理 | 虚构中间服务，异步调用画成同步完成 |
| 系统流程 | 校验、状态条件、事务、失败与结束路径 | 把拒绝分支接回成功写入，丢合流或回环 |
| 数据流 | 请求/返回数据、业务处理、真实读写存储 | 用“下一步/成功/失败”代替数据名称 |
| 架构 | 依赖/装配/启动/部署配置及实际调用 | 把装了依赖但没用的 Redis、队列、微服务画进去 |
| 用例 | 实际角色权限与业务目标 | 默认每个角色都有 CRUD，用图表新增后台权限 |

领域类图以业务领域类型为主；Controller、DTO、Repository 等技术类用于时序/架构。若项目采用贫血模型，按真实实体/枚举和关系表达，不为“好看”添加不存在的行为。

## 跨图一致性

1. 功能树与用例图的角色/目标一致，操作范围与后端实际授权一致。
2. 时序图中的业务对象和调用存在；流程图中的条件、状态和时序分支一致。
3. DFD 的每条读写有代码依据；顶层、一层、各二层边界数据名称、方向和对端平衡。
4. 架构图的组件、存储和通信方式与部署事实一致；不要把业务主从归并误写成数据库表已经合并。
5. 被删除的功能、类、关系、角色记录到移除清单，不能继续保留为“现有能力”。
6. SQL 重设计后核对最终表/字段、视图、存储过程、触发器和应用调用。时序与流程表达真实事务和数据库内副作用；DFD 区分读取视图与底层存储，视图不自动成为新数据存储；架构不把过程/触发器画成独立服务器。
7. 对象处于“仅设计/教学示例”时不得标作已部署或应用已调用；若应用仍直接执行 CRUD，就不能凭过程定义文件改画为过程调用。依据不足的接入状态写入未验证清单。

## 输出与手动应用

- 七类图分别交付。系统流程、DFD、时序、用例各交付一个完整图族文件，不把一张图当成整个类别已完成，也不默认让用户切换多张图重复粘贴。
- 系统流程按实际核心业务目录生成：真实登录为login根图，其余每个核心场景独立分节。先核对覆盖清单，不能机械为每张表复制一张CRUD图，也不能只选择最容易的一个流程。
- DFD提供完整顶层、一层及需要展开的全部二层。二层节标题必须注明真实父加工编号；内部细节根据实际读取、校验、写入、返回数据拆解。父子边界的对端、方向和数据名称一致，不能把层级关系交给用户手动补。
- “一段正文”指一份连续、带分节标题的原生文本，不是几个独立代码框。系统流程以`# 系统流程图图族 v1`开头；DFD以`# 数据流图图族 v1`开头；每张图使用`##`节。模型不要输出内部figureId或自造绑定命令。
- 用户先备份旧稿，在对应类别的“快速填写”粘贴整份正文，点击一次“应用并保存全部图”。所有成员整体校验与持久化，任何错误整批拒绝并保留草稿；旧成员未包含在全文中会移除。不能改用循环逐张POST或人工多次粘贴冒充一次原子应用。
- 其他图种按其实际入口应用。功能树核对角色绑定和显示深度；时序用一个文件包含root总图及全部核心业务分节。类图与架构全文更新当前模型/成员；用例全文更新完整图族，包含所有保留角色及用例。
- 单图文本仅作为明确限定当前成员时的局部编辑方式，不能取代用户要求的整族更新。接收端缺少整族入口时明确版本不适配，不能让技能声称已经支持。

## 验证级别

分别标注：代码证据、原生解析、网站应用、真实保存及刷新回读。系统流程/DFD必须额外检查一次应用产生的全部成员数量与名称、旧成员移除、每张图恢复、DFD跨层边界证明和任一坏节整批拒绝。

图纸数量取决于真实核心业务清单，不固定为某个示例数量。独立测试夹具与用户实际项目分别标明；夹具验证不等于已经更改用户项目。原子保存不表示已经发布到线上，版本适配以本次实际源码、协议和浏览器证据为准。

## 真实产物必须验证

不能仅校验格式源码SHA或逐节解析就声称完整产物可用。将用户项目最终文本整份交给正式整套解析器，核对成员数、名称、往返及父子平衡，再验证投影和布局。DFD先制作父处理边界清单（对端/方向/数据名称），下层复用相同词汇；额外读写需要按代码证据在父层同步，不可只改文字凑平衡。错误应针对具体边界修正，不删除核心业务、不跳过聚合验证。

功能树module/operation/detail分别测可见节点、无重叠、末端间距；隐藏子层不能继续占用完整树的宽度。架构快速填写后核对新节点与连接、旧模板几何是否清除，不能把过程/触发器当独立服务器。七类每类只有一份最终正文。
