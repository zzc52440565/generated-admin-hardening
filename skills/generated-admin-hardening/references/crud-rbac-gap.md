# CRUD 项目中的常见契约缺口

按证据选择检查，不把以下项目扩展为必做产品清单。

- 数据：业务唯一性由数据库/事务保障；索引按真实查询评估；软删除、历史保留与唯一冲突一致；不直接加一套新字典/权限表。
- API：入口校验、统一错误、后端鉴权、批量对象归属；状态/金额在服务端计算。重试敏感操作按真实需求实现幂等，不凭空要求所有接口都引入幂等键。
- 前后端：命名映射、枚举值、金额精度、空值、时区、分页/排序/筛选参数与返回模型一致。
- 业务：现有状态链路完整、前置条件明确、关联修改在事务内；没有需求的收费、通知、报表、审批或调度只作为建议。
- 可运维性：依赖版本与启动命令真实，错误可追踪，日志脱敏，配置分环境；不把健康探针通过当业务验收。

验收采用具体触发→请求→返回→数据结果链路。改造后图表中的状态、数据流和操作必须与这些事实一致。
