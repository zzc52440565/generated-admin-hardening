# 系统流程图：整族快速填写

默认一次覆盖登录及全部核心业务。稳定英文标识用于辨认成员，名称写实际业务；`login`是登录根图，每个标识唯一。每张图的步骤编号在本节内独立，显式连接不得跨节引用。网页会创建对应成员，不要求用户预先手工建图。

```text
# 系统流程图图族 v1
## 流程：login | 统一登录
[1] 开始
[2] 处理：校验真实登录凭据
[3] 结束
连接：1 -> 2
连接：2 -> 3

## 流程：order-submit | 提交订单
[1] 开始
[2] 判断：输入与权限有效？
[3] 处理：保存订单
[4] 输入输出：返回校验错误
[5] 结束
连接：1 -> 2
连接：2 -> 3 | 是
连接：2 -> 4 | 否
连接：3 -> 5
连接：4 -> 5

## 流程：order-fulfill | 履约处理
[1] 开始
[2] 判断：订单可履约？
[3] 处理：更新履约状态
[4] 结束
连接：1 -> 2
连接：2 -> 3 | 是
连接：2 -> 4 | 否
连接：3 -> 4
```

示例只演示协议。生成时必须依据优化后项目的全部核心入口重新写；一份正文一次复制到“整族快速填写”，点击“应用并保存全部图”。首行、`## 流程：标识 | 名称`和各节正文都需保留。未包含的旧成员会移除；任何非法连接、重复标识、缺login或容量超限整批拒绝。当前最多登录加24张业务流程，正文250000字符；不能靠分段覆盖或忽略业务来绕过容量，超限需报告产品限制。

# 系统流程图快速填写

依据：`systemFlowchartStructureText.ts::parseSystemFlowchartStructureText`。`flowchartQuickFill.ts::buildFlowchartSpecFromQuickFill` 在系统流程图中优先解析此编号格式。

优先输出编号步骤与显式连接，保留多入边、合流和回环。先声明全部节点，再列连接；第一行必须直接是 `[编号]`，否则可能退回旧缩进解析。

```text
[1] 开始
[2] 输入输出：提交商品与数量
[3] 判断：参数是否有效
[4] 处理：保存订单
[5] 输入输出：返回订单编号
[6] 处理：提示修改输入
[7] 结束

连接：1 -> 2
连接：2 -> 3
连接：3 -> 4 | 是
连接：3 -> 6 | 否
连接：4 -> 5
连接：5 -> 7
连接：6 -> 7
```

- 编号为不重复正整数，建议从 1 连续递增。连接必须引用已声明编号，不能写名称或先连后声明。
- 类型支持 `起止 / 处理 / 判断 / 结果判断 / 循环判断 / 输入输出 / 数据存储 / 文档 / 子流程`；纯 `开始`、`结束` 可直接使用。自定义端点写 `起止：办理结束`，不要写 `[7] 结束：...`。
- `连接：源编号 -> 目标编号 | 标签`；标签可省略。分支写真实条件或结果，结束节点没有出边，合法回环必须来自真实代码。
- 节点/标签中的换行写字面 `\n`，反斜线写 `\\`；不把说明或代码围栏粘进正文。
- 图稿在当前成员内按节点和边重建。核对每个决策的所有分支，尤其失败分支不能误入成功写入。

这套编号协议只用于**系统流程图**。实体生命周期的“批量构建”使用旧缩进语法，不能混用；用户要求后者时读取其当前样例并适配。示例文件 `assets/quick-fill-examples/04-system-flowchart.txt`。
