# 数据流图：整族快速填写

默认一次生成顶层、一层和所有需要展开的二层，使用一个连续文本文件。网页“整族快速填写”一次创建/更新全部成员并原子保存，不能默认拆成让用户多次粘贴的单图文件。

```text
# 数据流图图族 v1
## 顶层数据流图
外部实体："客户"
处理："0 订单系统"
数据流："客户" -> "0 订单系统"："订单资料"
数据流："0 订单系统" -> "客户"："订单结果"

## 1层数据流图
外部实体："客户"
处理："1.0 受理订单"
数据存储："D1 订单库"
数据流："客户" -> "1.0 受理订单"："订单资料"
数据流："1.0 受理订单" -> "D1 订单库"："订单记录"
数据流："D1 订单库" -> "1.0 受理订单"："订单状态"
数据流："1.0 受理订单" -> "客户"："订单结果"

## 2层数据流图：1.0 | 受理订单
外部实体："客户"
处理："1.1 校验订单"
处理："1.2 保存并查询订单"
数据存储："D1 订单库"
数据流："客户" -> "1.1 校验订单"："订单资料"
数据流："1.1 校验订单" -> "1.2 保存并查询订单"："已校验订单"
数据流："1.2 保存并查询订单" -> "D1 订单库"："订单记录"
数据流："D1 订单库" -> "1.2 保存并查询订单"："订单状态"
数据流："1.2 保存并查询订单" -> "客户"："订单结果"
```

- 首行固定`# 数据流图图族 v1`。顶层和一层各一节；每张二层使用`## 2层数据流图：父编号 | 名称`。父编号必须对应本段一层加工，不能用未绑定的二层图替代。每个父加工最多一张二层；一个原子加工不强造细节，在覆盖清单解释依据。
- 声明前缀为`外部实体：`、`处理：`、`数据存储：`。数据流为`数据流："起点" -> "终点"："数据名"`。名称和数据名使用JSON双引号，内部引号和换行使用JSON转义。每节先显式声明全部端点，名称完全一致。
- 顶层只有一个编号0的系统加工、外部实体与边界流；一层编号1.0/2.0；二层按真实父加工编号使用1.1/1.2等。共享存储和外部实体名称保持一致。二层涉及其他一层加工时在当前节显式声明其原编号和原名。
- 每张二层必须覆盖其父加工全部边界输入输出；数据名、方向、对端与一层一致。一层外部边界同样与顶层一致，内部加工之间可用真实细化数据流。不能省略父接口，也不能把“是/否/下一步”当成数据名。
- 每条数据流至少连接一个加工；拒绝悬空端点、绕过加工、空数据名、重复声明、错误父加工和不平衡边界。任何一节错误时整个图族不变，草稿保留。全文中未包含的旧二层成员会移除。
- 完整正文最多250000字符，并受图族现有节点/成员容量约束。超限写明限制，不能要求用户分段覆盖。不要输出内部figureId、JSON family存储结构或自造`父处理`命令。
- 单图解析和逐项编辑仍是局部修改方式；不能把“只有当前成员被修改”称为整族应用。接收端旧版没有批量入口时须明确需要升级，不以删除标题或直接POST绕过校验。

验证要同时核对批量解析器`figureFamilyQuickFill.ts`、图族编辑器`dataFlowDiagramFamilyEditing.ts`、合法性校验与持久化。结果至少覆盖一次应用产生所有图、真实保存/刷新回读、边界映射和坏节整批拒绝。
