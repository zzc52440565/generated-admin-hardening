# 权限核对与必要重构

先盘现状，不能把“脚手架权限都不可信”当成必须重做的证据。

1. 从服务端授权、角色配置、行范围、字段白名单、文件与任务入口建立事实矩阵。
2. 与已确认业务职责比较。角色推导是建议，新增角色或改变职责须在当前授权需求内；不能仅为了完整而重建 RBAC。
3. 按角色核对菜单可见、操作可用、数据范围和字段可读写。前端隐藏仅改善体验，不能代替后端拒绝。
4. 复用统一鉴权与查询范围，不把多个手写判断散落到调用方。按 ID、批量、导出、下载、子资源和后台任务都须绑定真实主体/租户上下文。
5. 以隔离测试账号执行正向和负向行为：未认证、跨角色、跨用户/租户、越权字段、伪造明细归属、异步执行时权限变化。记录状态码和“无业务副作用”，不能只测前端。
6. 修正后对受影响角色矩阵回归；图表记录实际角色，不让用例快填反过来创造权限。

不要为了便于测试记录验证码、记录真实口令或增加认证后门；本地演示账号统一123456并使用真实编码器，不影响真实/生产账号。登录困难使用现有测试 fixture、预先登录的会话或用户提供的授权方式。日志、报告和公网包不得包含真实令牌。
