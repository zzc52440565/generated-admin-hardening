## SQL规范审查场景

- MySQL/SQL Server目标：所有对象使用目标版本，客户端分隔符和驱动执行分开；不把高级对象混进结构导入承诺自动恢复。
- SQLite目标：明确没有服务端存储过程，视图和触发器的引擎能力与当前章节输出策略分开；不得产生MySQL过程语法。
- 规则已在服务中写入：不能再加触发器重复累计/扣减；替换owner需迁移全部入口和测试。
- 有现存数据：空库方案与增量迁移/恢复分开；生成脚本不等于获得生产执行权限。
- 没有具体SQL：输出流程与待核对事实，不编造业务对象、执行结果或EXPLAIN数字。
- 仅教学对象：标记未接入应用，不能在七图中画成实际运行能力。

以上为规范一致性审查，不是独立模型执行或数据库实测。
