## 审查结论

原技能的检查方向有价值：空选项、无效筛选、权限、主从单据、实际尺寸及运行时验证，覆盖了生成项目常见缺口。但不宜按原样公开给用户直接执行，主要存在以下问题。

| 问题与证据 | 影响 | 本版处理 |
| --- | --- | --- |
| 主入口超过 21 KB，description 过长且重复；便携版独立维护 | 发现成本高、规则容易漂移 | 缩短入口，按需引用；便携版由同源构建 |
| 默认重建演示数据、固定数据库限制，又要求主动补所有核心业务 | 数据保护与范围相冲突 | 以需求/证据和现有数据为准，隔离种子与真实数据 |
| 认为 RBAC 必须重做，按业务推导角色后直接改 | 容易改变用户职责和权限 | 先事实矩阵，只修授权范围内偏差 |
| 验证码打 debug 日志/测试后门、固定 admin/123456、租赁模块硬编码 | 认证泄漏与跨项目误用 | 删除日志登录、密码和模块默认，使用现有会话 |
| 每轮强制 commit、未规定完成边界 | 自动提交、无限扩展 | 提交由用户决定，明确完成与未验证状态 |
| 默认 301、级联删明细、原生 SQL 绕过逻辑删除 | 容易丢历史或绕过范围授权 | 按真实路由/生命周期，保持租户与授权范围 |
| 按钮只认弹窗/下拉/提示，忽略导航下载；所有按钮直接点 | 误报及真实写入风险 | 清单白名单、明确预期，仅已审查只读操作 |
| 关闭弹窗点击第一个 footer 按钮 | 可能点击提交/确认 | 仅 Escape；不点未知 footer；JS 对话框取消 |
| 筛选依赖 GET 参数和当前行数，失败不返回非零码 | 漏掉 POST、后端无效过滤，自动化假通过 | 支持 GET/POST，核对请求值和明确结果，失败码分层 |
| 无正式图表协议，缺安装/发布说明与 UI 元数据 | 用户难安装，图表可能无法粘贴 | 新增七图资料、元数据、安装器、发布包与验证工具 |
| 包中私有技能路径和个人案例被视为通用默认 | 用户环境不兼容，复制样例业务 | 自包含目录，去除个人案例依赖，格式例子明确为演示 |

## 2.0.0历史：七图接收能力事实

原2.0.0发布时，功能结构、时序、系统流程、DFD 是当前图内重建；领域类图与用例图是增量，不能靠文本删除旧项。架构图当前没有通用快速填写入口，提供可视化编辑清单。

因此，要求“七图都一贴替换”超出当前产品能力。技能已把各图的可执行方式写清；如果需要架构文本导入及类图/用例全量替换，需要单独修改 Studio 产品实现，本轮没有改动产品代码。

## 原2.0.0验证边界

本轮验证的是技能内容、分发工具、可选审计脚本及内置示例与当前解析器的兼容性。没有用本技能对一个真实客户项目完整加固，也没有代替用户把图贴入其项目、发布公网或提交插件审核。具体结果见 [VALIDATION.md](VALIDATION.md)。


## 2.2.2 真实项目与完整图族复核

新增两项有实测依据的能力：DFD合法内容编辑及完整family持久化；系统流程和DFD的默认整族一次填写。协议、原子拒绝、父子映射、容量、旧成员移除和网站版本依赖均已写入技能。真实案例覆盖17系统流程和7DFD，并完成桌面/手机保存恢复。
