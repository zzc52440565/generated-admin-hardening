# 2.2.1 自查、自检与纠正记录

验收日期：2026-11-03。本轮重新审查产品、技能与发布包，不把2.2.0旧结果冒充新执行。修复前新增的4项行为回归均失败，另22项通过；修复后全部通过。旧2.2.0下载物和证据保留。

## 已纠正

1. 架构新增同名节点时，新生成ID可能与复用节点冲突，合法全文会被误拒绝。新ID现预留全部已有身份。
2. 在旧连线前插入新连线，可能生成相同ID。现在新增和复用的连线身份独立。
3. 类成员ID只保证类内唯一，原全局保留集合会错误保留另一类已删除成员。现以类ID和成员ID共同匹配。
4. 新增依赖行写在保留关联行之前时，旧关系身份和元数据被提前抢占。现根据全文预留仍需保留的关系种类。
5. 用例字符/行数超限仍提示分次填写，规范后部也残留增量说明。现统一全文语义，超限建议精简或逐项编辑。
6. 扩展检查发现相邻Workspace测试仍断言旧增量命令与反馈。已迁移并增加实际reducer/物化结果断言，验证完整替换后仅保留新角色与用例。

## 架构展示边界与早期失败

浏览器新增断言第一轮有2项架构用例失败，原因是预期可见连线文字。进一步读取真实渲染器与既有测试，确认四种预置架构排版原本不绘制连线和箭头，关系语义仍存储并可回填。该行为没有被本轮改动；不把它虚报为已支持箭头，也不擅自改变渲染器或导出。回归改为验证两条关系规范化回填及独立编辑句柄，最终4项重新通过。该边界已同步技能。

打包检查器曾误用只在README中出现的词作为便携版断言，现改为核对架构、类图、SQL三份参考全文完整收录；检查器修正后通过，不改变协议含义。

证据保存于本机独立目录 `本地独立验收目录（未公开）`：故障基线、浏览器失败trace/截图、最终截图、健康检查和包检查结果。它们不进入公网源码包。独占Next服务使用3167端口，直接Next入口并显式关闭Web会话恢复，不迁移、不生成Prisma、不启Worker；服务与缓存由本轮清理。
